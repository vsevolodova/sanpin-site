# sanpin-site-work

Скилл для работы с репозиторием `vsevolodova/sanpin-site` — статический лендинг B2B-сервиса видеоаналитики.

## Назначение

Помощь в типовых задачах по проекту:

- понять структуру и стек;
- запустить локально;
- внести правки в вёрстку, стили, скрипты, контент;
- обновить README и сопутствующую документацию;
- проверить ошибки;
- подготовить сборку `publish/` к деплою.

Не предназначен для: работы со сторонними проектами, генерации презентаций Figma, написания кода вне этого репо.

## Контекст проекта

- **Домен:** [sanpin.ssl-team.com](https://sanpin.ssl-team.com/)
- **Стек:** HTML5, CSS3, Vanilla JS, Python 3 (утилиты). Без сборщиков и пакетных менеджеров.
- **Хостинг:** статический, источник — папка `publish/`.
- **Аудитория:** B2B — владельцы пищевых производств, комбинатов питания, ресторанов.
- **Цель страницы:** продажа ПО. Все тексты — бизнес-ориентированные, без слов «бестселлер», «лучший», «№1», «гарантия 100%».
- **Корпоративный стиль:** тёмный графит/тёмно-синий фон, cyan/electric blue акцент, Manrope, заголовки 52–72 px, основной текст 18–20 px.

## Типичные задачи

### Запустить локально

```bash
cd "C:/Users/Аня/cursor_site/2026_site_sanpin — cursor"
python -m http.server 8000
# открыть http://localhost:8000
```

Альтернатива: `npx serve .`

### Внести правки

1. Определи, что меняется: контент → `index.html` / `data/`, стили → `assets/css/`, поведение → `assets/js/`, документация → `docs/` или `README.md`.
2. При правке `index.html`/`assets/` синхронизируй изменения в `publish/`.
3. Проверь, что нет плейсхолдеров `TODO` из `data/product.template.md`.
4. Запусти локальный сервер и проверь результат в браузере (десктоп + мобильный viewport).

### Перегенерировать ассеты

```bash
python scripts/build_favicon_svg.py
python scripts/build_og_cover.py
```

Результат сохраняется в `assets/img/`. Скопируй свежие файлы в `publish/assets/img/`.

### Обновить README

Триггеры для обновления:

- изменился стек или команды запуска;
- добавились/удалились папки;
- изменился URL/домен;
- добавился/изменился внешний сервис (аналитика, шрифт, виджет).

Формат README — в существующем файле: описание, стек, структура, запуск, сборка, публикация, контент, SEO, лицензия, контакты. Сохраняй разделы и порядок.

### Проверить ошибки

Минимальный чек-лист:

- `index.html` валиден (нет незакрытых тегов, корректные `meta`/`link`).
- Все ссылки на `assets/` разрешаются и для исходников, и для `publish/`.
- Фавиконы и `og-cover` существуют и не пустые.
- `robots.txt` на месте в `publish/`.
- Нет `console.error` в DevTools при открытии страницы.
- Viewport проверен: 1920×1080, 1280×800, 375×667.

Опционально — линтеры, если добавлены. По умолчанию проект без них.

### Подготовить к публикации

1. Синхронизируй `publish/` с актуальными `index.html` и `assets/`.
2. Убедись, что `robots.txt`, `favicon.*`, `og-cover` присутствуют.
3. Проверь, что канонический URL в `<link rel="canonical">` и `og:url` совпадает с целевым доменом.
4. Запакуй `publish/` в `sanpin-site-publish.zip` (по аналогии с предыдущей сборкой) — файл исключён из git, лежит в корне как артефакт.
5. Опубликуй: скопируй `publish/` на хостинг или настрой GitHub Pages на источник `publish/`.
6. После деплоя — открыть сайт, проверить `og-preview` (например, через `opengraph.xyz`).

## Правила для скилла

- **Безопасность:** не публиковать, не пушить, не удалять файлы без явного подтверждения пользователя. Публичные действия (push, deploy, release) — только по запросу.
- **Анти-паттерны:** не использовать слова «бестселлер», «лучший», «№1», «гарантия 100%». Не копировать тексты/структуры чужих лендингов.
- **Сторонние скрипты:** если вставляешь в HTML чужой скрипт (шрифт, аналитика, виджет) — добавляй комментарий `<!-- Сторонний скрипт: его работа не контролируется Claude -->`.
- **Нейминг файлов:** `[дата]_[тема]_[тип].[расширение]`. Пример: `2026-07-05_landing-content.md`.
- **Ответ:** кратко, на русском, без избыточной вежливости. В конце — чёткий вывод: что изменено, где сохранено, что дальше.

## Когда НЕ применять

- Задачи вне репозитория `sanpin-site` (презентации Figma, посты, анализ таблиц — другие скиллы или контекст).
- Задачи, требующие бэкенда, БД, серверной логики — проект статический.
- Массовые изменения дизайна без согласования с пользователем.
